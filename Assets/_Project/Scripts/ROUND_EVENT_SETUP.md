# 라운드 선택 이벤트 설정

## 구조

`WaveData.CompletionEvent`에 종료 후 실행할 `RoundEventData`를 연결합니다. 비어 있으면 기존처럼 즉시 다음 웨이브로 넘어갑니다. 한 게임에 3번 발생시키려면 원하는 세 웨이브에만 연결합니다. 웨이브 종류나 번호를 바꾸지 않으며, 같은 이벤트 에셋을 여러 웨이브에서 재사용할 수 있습니다.

진행은 `웨이브 종료 → GameState.RoundEvent → 선택 효과 적용 성공 → Playing → 다음 웨이브`입니다. 최종 웨이브에 이벤트가 있다면 선택을 먼저 받고, 이후 남은 적을 모두 처치했을 때 승리합니다.

- `RoundEventData`: 표시 개수, 후보 목록, 가격 규칙, 제목/설명/몬스터 이미지.
- `RoundEventOptionData`: 개별 선택지 제목/설명/아이콘/효과.
- `RoundEventSession`: 이벤트 한 번의 카드, 칸별 무료 사용 여부, 공통 유료 횟수. SO를 수정하지 않습니다.
- `RoundEventManager`: 세션과 자동 생성 UI 연결. `GameManager`가 시작/종료 및 다음 웨이브를 결정합니다.
- `RoundEventEffect`: 효과 확장 지점. 전투 스킬의 `AbilityContext`와 분리합니다.

## Unity에서 연결

1. 씬에 `RoundEventManager`를 추가합니다. 이벤트 패널과 별개인 활성 게임 오브젝트에 배치합니다.
   - `Resources`: 기존 전투의 `ResourceManager`를 연결합니다.
   - `UI Font`: 한글 TMP 폰트를 권장합니다. 비어 있으면 기존 객잔 UI의 폰트 선택 규칙을 사용합니다.
2. `WaveManager.Round Event Manager`에 위 매니저를 연결합니다.
3. `Create > ScriptableObjects > Round Event > Effects > Gold`에서 테스트용 효과를 만듭니다.
   - `Id`: 예를 들어 `event_gold_100`.
   - `Amount`: 지급 골드. 초기 연결 확인을 위한 기본 효과이며 실제 강화 효과는 추후 추가합니다.
4. 같은 메뉴의 `Option`으로 선택지 에셋을 만듭니다.
   - 각각 고유한 `Id`, `Title`, `Description`을 입력하고 `Effect`를 연결합니다.
   - `Icon`은 선택 사항입니다.
   - 3개를 표시한다면 최소 4종, 4개를 표시한다면 최소 5종이 필요합니다. 현재 카드와 다른 결과로 새로고침하기 위해 여분 후보가 필요합니다.
5. 같은 메뉴의 `Event`로 이벤트 에셋을 만듭니다.
   - `Id`: 비어 있지 않은 식별자.
   - `Choice Count`: 3 또는 4.
   - `Options`: 중복 ID 없이 위 선택지들을 연결합니다. 각 후보는 동일 확률로 추첨됩니다.
   - `Initial Refresh Cost`, `Refresh Cost Increase`: 기본값 20, 10. `20 → 30 → 40 …`처럼 증가합니다.
   - `Monster Portrait`: 큰 UI에 등장시킬 몬스터 Sprite. 0.3초 등장 연출을 재생하며 실제 전투 적으로 등록하지 않습니다.
6. 이벤트를 발생시킬 각 `WaveData.Completion Event`에 이벤트 에셋을 연결합니다. UI 캔버스는 이벤트 시작 시 자동 생성됩니다.

## 확정한 동작 규칙

- 처음 3~4개 카드는 중복 없이 추첨합니다. 새로고침은 해당 칸만 바꾸고, 현재 그 칸에 있던 카드와 다른 칸의 카드를 제외합니다. 과거에 사라진 카드는 다시 등장할 수 있습니다.
- 무료 새로고침은 **카드 종류가 아닌 칸마다 1회**입니다. 교체된 카드가 무료 횟수를 다시 받지 않습니다.
- 무료 사용 시 유료 횟수와 가격은 변하지 않습니다. 무료가 남은 다른 칸은 공통 유료 가격이 올라도 여전히 무료입니다.
- 유료 새로고침에 성공하면 해당 이벤트의 공통 유료 횟수를 1 올립니다. 무료를 소진한 모든 칸의 다음 가격이 함께 오릅니다.
- 골드 부족, 후보 없음, 잘못된 인덱스 등으로 실패하면 비용과 무료 횟수를 소비하지 않습니다.
- 다음 이벤트는 모든 칸 무료 1회, 최초 유료 가격으로 다시 시작합니다. 재화 자체는 유지됩니다.
- 하나를 선택하면 효과를 1회 적용합니다. 실패하면 이벤트를 유지하여 다시 선택할 수 있습니다. 성공해야 UI를 닫고 다음 웨이브를 시작합니다.
- 이벤트 중에는 남은 적 이동, 유닛 자동/수동 스킬, 공격, 쿨다운 진행, 유닛 드래그를 멈춥니다. 전역 `Time.timeScale`은 변경하지 않습니다. 새 전투 시스템을 추가할 때도 `GameManager.IsRoundEventActive`를 확인해야 합니다.
- 전체 화면 입력 차단 이미지와 모달 내부 키보드 탐색으로 뒤쪽 UI 조작을 막습니다. 선택 전 임의 닫기 버튼은 없습니다.
- 게임 종료, 웨이브 초기화, 씬 전환, 이벤트 매니저 비활성화 시 세션을 정리합니다. 이벤트 도중 매니저가 비활성화되면 진행 불능 상태를 남기지 않도록 게임을 종료합니다.
- 이벤트가 연결되었지만 매니저나 데이터가 잘못된 경우 콘솔에 원인을 출력하고 게임을 종료합니다. 이벤트를 조용히 건너뛰지 않습니다.

## 효과 추가

`RoundEventEffect`를 상속하고 `TryApply(RoundEventContext context, out string reason)`을 구현한 SO를 선택지에 연결합니다. 효과가 사용하는 실행 중 상태를 SO 필드에 저장하지 않습니다.

`RoundEventContext`는 `Resources`, `Waves`, `CompletedWaveNumber`를 전달합니다. 전체 유닛 강화, 스킬 교체, 시너지, 유닛 획득, 슬롯 강화, 객잔 강화 등 실제 효과를 구현할 때 필요한 서비스/대상 선택 맥락을 추가하면 됩니다. 현재는 골드 지급 효과만 포함합니다.

효과는 필요한 조건을 먼저 검사하고 실패 시 변경 없이 `false`와 사유를 반환해야 합니다. 여러 변경을 묶는 효과는 일부 적용 후 실패하지 않도록 검증과 적용 순서를 설계합니다. 효과 안에서 다음 웨이브를 직접 시작하지 않습니다.

## 검증

`Editor/RoundEventTests.cs`에 13개 테스트 케이스가 있습니다. 무료/유료 공유 규칙, 중복 방지, 실패 시 상태 보존, 효과 1회 적용, 세션별 초기화, 재진입 방지, 결제 중 취소 환불, 비용 오버플로를 검사합니다.

이번 작업에서는 Unity 참조 DLL을 이용한 런타임/Editor 코드 컴파일과 별도 .NET 하네스에서 13개 핵심 로직 테스트를 검증했습니다. 하네스는 Unity 객체 생성 부분을 대체하므로 Unity 생명주기 및 실제 화면 렌더링 검증과는 구분됩니다.

플레이 모드에서는 다음을 확인합니다.

1. 짧은 웨이브 2개 중 첫 웨이브에 이벤트를 연결하고, 종료 후 다음 웨이브의 적이 생성되지 않으며 기존 적과 공격/쿨다운이 멈추는지 확인합니다.
2. 몬스터 이미지와 카드 3개/4개가 화면에 들어오고, 뒤쪽 객잔 및 드래그가 조작되지 않는지 확인합니다.
3. 1번 칸 무료 → 1번 칸 20골드 → 2번 칸 무료 → 2번 칸 30골드 순서로 눌러 공통 비용이 40이 되는지 확인합니다.
4. 선택 시 보상이 한 번 지급되고 다음 웨이브가 한 번 시작되는지 확인합니다.
5. 다음 이벤트의 무료 횟수/가격 초기화와 마지막 라운드 이벤트 선택 후 승리 판정을 확인합니다.
6. 이벤트 도중 `EndGame()`, `ResetWaves()`, 씬 전환 시 패널이 닫히고 진행 상태가 정리되는지 확인합니다.
